# OnFilm 프로젝트 면접 질문 총정리

- 작성일: 2026-09-08
- 범위: 프로젝트 소개·설계·구현·검증·장애·성능·인프라·협업과 AI 활용
- 구성: 26개 영역, 총 260문항. 질문 목록이며 모든 항목의 구현 완료를 의미하지 않는다.
- 전체 답변: [Q001~Q260 면접 답변](13-onfilm-project-interview-answers.md). 같은 번호로 짧은 답변과 검증 범위·한계를 정리했다.
- 표기: 각 영역 첫 질문의 **핵심** 표시는 우선 준비할 26문항이다. 체크는 암기 여부가 아니라 본인 코드·근거·한계까지 설명할 수 있는지를 기준으로 한다.
- 활용: 기존 단원별 답변을 다시 복사하지 않고 관련 문서로 연결한다. 미구현 대안은 ‘검토 방향’으로 답하고 실제 사용자 운영·실험·자동화 테스트를 구분한다.

## 준비 방법

각 답변을 ‘문제 → 원인 → 선택한 방법 → 다른 대안 → 검증 근거 → 남은 한계’로 준비한다. 30초 핵심 답변과 2분 상세 답변을 따로 연습한다.

- 확인할 근거: 클래스·메서드, 테스트 이름, Migration, 실험 조건, 로그·지표, 커밋과 작업 날짜
- 상태 분류: 설명 가능 / 근거 확인 필요 / 추가 학습 필요 / 미구현·확장 방향
- 아래 질문은 실제 면접 출제 목록이 아니라 OnFilm 기록에서 도출한 준비용 질문이다.

## 면접 전에 설명을 맞춰 둘 항목

다음은 자료 확인 중 드러난 설명상의 주의점이다. 이번 작업에서는 기존 문서나 코드를 고치지 않고 질문으로 연결했다.

- 아키텍처: README의 ALB·Private Subnet·CodeDeploy 설명과 단기 측정 환경의 Default VPC·직접 SCP 배포를 같은 구성으로 말하지 않는다. 환경과 시점을 붙인다. → Q221, Q232
- 성능: 초기 k6 결과, 이후 AWS 재측정, MySQL 전용 SQL 벤치마크는 별도 실험이다. 숫자마다 날짜·커밋·데이터·부하 모델·성공률·표본을 붙인다. → Q185~Q200
- Query 성능: 123ms→3.40ms는 문서의 완료 Job ID 조회 SQL 결과다. API 전체나 대량 DELETE 속도로 확장해서 주장하지 않는다. → Q191~Q192
- Retry: 현재 공통 Worker Retry Topic 정책과 단계별 긴 대기 일정 목표를 구분한다. → Q152~Q156
- 트랜잭션 이후 삭제: 프로세스 내 AFTER_COMMIT 이벤트는 영속적인 삭제 작업 큐가 아니다. 현재 리스너의 실패 로그 수준도 코드 기준으로 확인한다. → Q112~Q114
- 인증: Refresh Token 전체 삭제는 발급된 Access Token의 즉시 차단과 다르다. 현재 CSRF 제외·출처 비교의 한계도 설명한다. → Q085, Q089
- 멱등성: 같은 Job의 결과 중복 방지와 외부 FFmpeg의 정확히 한 번 실행은 다르다. 서로 다른 Job이 같은 Movie를 갱신하는 문제도 별개다. → Q149, Q157
- 운영: AWS 테스트 중 실제로 겪은 장애와 소수 사용자 운영 정책, 대규모 실서비스 운영 경력을 구분한다. → Q006, Q220
- 검증: 테스트 수는 특정 커밋 시점의 기록이다. 테스트 통과만으로 모든 네트워크·종료·복구 상황을 검증했다고 주장하지 않는다. → Q207~Q209

## 준비 우선순위

1. 각 영역의 **핵심** 26문항에 30초 답변을 만든다.
2. 대표 사례 세 개를 고른다: Outbox·Inbox, 조회 최적화, Callback 장애 추적. 각 사례에 코드·테스트·실험 기록을 연결한다.
3. 사례마다 ‘대안은?’, ‘어디까지 보장하나?’, ‘다시 실패하면?’, ‘직접 한 판단은?’에 답한다.
4. 빈약한 근거는 꾸미지 않고 ‘미측정’, ‘미구현’, ‘추가 검토’로 표시한다.
5. 시간이 남으면 지원 직무와 가까운 영역의 세부 질문을 확장한다. 목록 전체를 같은 우선순위로 외울 필요는 없다.
