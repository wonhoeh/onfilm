# Movie 영상 이용 권한은 MVP에서 수동으로 확인한다

- 상태: Accepted for MVP
- 결정일: 2026-09-01
- 재검토 시점: 불특정 사용자를 받는 공개 서비스 전환 전

## 배경

OnFilm의 현재 목표는 불특정 다수가 이용하는 공개 플랫폼이 아니라, 운영자가 알고 있는 1~2명의 사용자가 회원제로 필모그래피와 영상을 관리하는 소규모 MVP다.

배우는 작품에 참여했다는 이유로 자신의 필모그래피를 등록할 수 있지만, 그것만으로 원본 영상을 저장·인코딩·스트리밍할 권한까지 자동으로 얻는 것은 아니다. 영상저작물은 계약과 제작 관계에 따라 실제 이용 권한자가 감독, 영상제작자, 제작사 또는 배급사 등으로 달라질 수 있다. 저작권법의 영상저작물 특례도 실연자의 복제·배포·방송·전송권이 특약이 없는 경우 영상제작자에게 양도된 것으로 추정하는 규정을 두고 있다.

참고 자료:

- [한국저작권위원회 영상저작물 상담 사례](https://www.copyright.or.kr/business/counsel/auto-advice-service/practice/detail.do?categorySeq=0&categoryType=&counselSeq=3556&parCategorySeq=)
- [국가법령정보센터 저작권법](https://www.law.go.kr/LSW/lsSc.do?query=%EC%A0%80%EC%9E%91%EA%B6%8C%EB%B2%95)

전자서명, 권리자 본인 확인, 이용허락 상태 머신과 분쟁 처리 시스템을 지금 모두 구현하면 현재 이용 규모에 비해 개발·운영 범위가 지나치게 커진다. 따라서 MVP에서는 권리 확인을 운영 절차로 처리하고, 공개 서비스 전환 시 시스템으로 확장한다.

## 현재 결정

### 작품·참여·영상 권한을 구분한다

```text
Movie
→ 여러 참여자가 공유하는 작품

MoviePerson / MoviePersonRole
→ 개인의 작품 참여 이력과 역할

영상 이용 권한
→ 운영자가 별도로 확인하는 공개 조건
```

작품에 참여했다는 사실과 영상을 공개할 권한은 서로 다른 조건으로 취급한다.

### 같은 작품은 하나의 Movie로 관리한다

같은 작품에 참여한 사람이 여러 명이어도 Movie와 영상 파일을 참여자별로 복제하지 않는다.

```text
Movie: 1개
MovieMedia: 1개
MoviePerson: 참여자 수만큼
MoviePersonRole: 각 참여자가 맡은 역할 수만큼
```

참여자는 기존 Movie에 자신의 `MoviePerson`을 추가한다. 자신의 필모그래피에서 작품을 제거하거나 회원탈퇴하더라도 자신의 참여 관계만 제거하며, 다른 참여자의 관계와 공유 Movie는 유지한다.

관련 모델링 결정은 [Movie 참여와 역할 모델링 정책](movie-person-role-modeling-policy.md)을 따른다.

## MVP 운영 정책

### 이용 대상

- 운영자가 알고 있는 1~2명의 사용자만 이용한다.
- 사용자를 받기 전에 영상 업로드 목적과 권리 관계를 운영자가 직접 확인한다.
- 권리 관계가 불명확하면 영상은 받지 않고 텍스트 기반 필모그래피만 허용한다.

### 권리 확인

현재는 애플리케이션 안에 전자서명이나 자동 승인 기능을 구현하지 않는다.

운영자는 영상 업로드 전에 다음 내용을 수동으로 확인한다.

- 실제 복제·인코딩·인터넷 공개를 허락할 수 있는 주체가 누구인지
- 사용자가 해당 권리자이거나 이용허락을 받았는지
- OnFilm 서버 저장, 포맷 변환, HLS 인코딩과 스트리밍 제공이 허락 범위에 포함되는지
- 공개 기간과 공개 범위에 제한이 있는지
- 허락 철회 또는 만료 조건이 있는지

단순히 작품에 출연했다는 진술만으로 영상 공개를 승인하지 않는다.

### 증빙 보관

- 계약서, 이용허락서, 권리자 연락처 같은 민감한 자료를 Git 저장소와 일반 문서 디렉터리에 저장하지 않는다.
- 필요한 경우 접근이 제한된 개인 보관소에 저장한다.
- 저장 목적과 보존 기간이 끝나면 삭제한다.
- 저장소에는 실제 개인정보나 계약서가 아니라 정책과 확인 항목만 기록한다.

### 애플리케이션 범위

MVP에서는 다음 기능을 구현하지 않는다.

- `MediaUsageGrant` 엔티티
- 권리자 회원가입과 본인 확인
- 이메일·SMS 기반 일회용 승인 링크
- 전자문서 서명
- 자동 권리 승인
- 권리 만료·철회 상태 머신
- 영상 Hash 기반 자동 중복 병합
- 저작권 분쟁과 이의 제기 Workflow

이 기능을 구현하지 않는 대신, 서비스 이용자를 제한하고 업로드 전에 운영자가 직접 확인하는 방식으로 범위를 통제한다.

## 삭제 정책

### 필모그래피에서 작품 제거

```text
사용자가 자신의 작품을 필모그래피에서 제거
→ 자신의 MoviePerson과 MoviePersonRole 삭제
→ 공유 Movie와 영상은 유지
```

### 회원탈퇴

```text
User 또는 Person 탈퇴
→ 해당 Person의 MoviePerson 삭제
→ 다른 참여자의 MoviePerson 유지
→ Movie를 User 삭제에 CASCADE하지 않음
```

탈퇴자가 최초 업로더여도 다른 참여자가 존재하고 기존 수동 이용허락이 계속 유효하다고 확인됐다면 Movie와 영상을 유지할 수 있다. 이용허락의 지속 여부가 불명확하면 Movie 메타데이터는 유지하되 영상 공개를 중단하고 운영자가 확인한다.

### Movie 자체 삭제

Movie 삭제는 개인 필모그래피 제거와 다른 관리 작업이다.

```text
Movie 삭제
→ MoviePerson 삭제
→ MoviePersonRole 삭제
→ MovieGenre·Trailer 등 Movie 소유 자식 삭제
→ DB 커밋 후 관련 스토리지 파일 삭제
```

다른 참여자가 있는 Movie는 일반 참여자 한 명의 요청만으로 삭제하지 않는다. 참여자가 없거나, 모든 관계자와 권리 상태를 운영자가 확인했거나, 관리상 강제 삭제 사유가 있는 경우에만 Movie 자체를 삭제한다.

## FK와 Cascade 방향

```text
Movie
  └─ MoviePerson
       └─ MoviePersonRole
```

- Movie 삭제 시 MoviePerson 삭제
- MoviePerson 삭제 시 MoviePersonRole 삭제
- Person 삭제 시 해당 Person의 MoviePerson 삭제
- Person 또는 User 삭제가 Movie 삭제로 전파되지는 않음
- Movie 삭제에 따른 실제 파일 삭제는 DB 트랜잭션 커밋 이후 실행

Flyway Constraint 감사에서는 이 방향을 기준으로 FK의 `ON DELETE` 정책과 서비스 삭제 흐름을 함께 검토한다.

## 공개 서비스 전환 시 확장 조건

다음 중 하나라도 발생하면 수동 정책을 재검토한다.

- 운영자가 모르는 사용자의 회원가입을 받음
- 영상 업로드 사용자가 지속적으로 증가함
- 권리자와 업로더가 다른 사례가 반복됨
- 이용허락 기간·지역·공개 범위를 시스템에서 관리해야 함
- 권리 철회나 저작권 신고가 접수됨
- 여러 관리자가 하나의 Movie를 관리해야 함
- 같은 영상의 중복 업로드가 실제 저장 비용 문제로 확인됨

## 공개 서비스 확장 모델

공개 서비스 전환 시 다음 모델을 단계적으로 추가한다.

```text
MovieManager
→ Movie 관리 권한과 소유권 이전

MediaUsageGrant
→ 권리자, 이용허락 범위·기간·증빙과 승인 상태

MovieMediaAsset
→ 원본·HLS·썸네일·Hash와 공개 상태
```

권장 상태 예시는 다음과 같다.

```text
MediaUsageGrant
PENDING → APPROVED
        → REJECTED
APPROVED → REVOKED / EXPIRED

MovieMediaAsset
WAITING_FOR_RIGHTS → UPLOADED → ENCODING → PUBLISHED
PUBLISHED → BLOCKED → DELETED
```

유효한 `APPROVED` 이용허락이 없으면 MediaAsset을 `PUBLISHED`로 변경하지 못하도록 한다.

권리자가 OnFilm 회원이 아니어도 다음 방식으로 승인할 수 있도록 확장한다.

1. 업로더가 권리자 연락처와 권리 근거를 제출한다.
2. 권리자에게 일회용 확인 링크를 발송한다.
3. 권리자가 저장·인코딩·스트리밍 범위와 기간을 확인한다.
4. 전자서명 또는 별도 증빙을 제출한다.
5. 승인 이후에만 업로드 URL과 공개 권한을 제공한다.

전자서명과 이용허락 문구는 공개 서비스 출시 전에 저작권 전문가의 검토를 받는다.

## 트레이드오프

### 얻는 점

- 현재 사용자 수에 맞게 구현 범위를 통제한다.
- 복잡한 권리 승인 시스템 없이 MVP 기능 검증에 집중할 수 있다.
- 작품 참여와 영상 권한을 개념적으로 분리해 향후 확장을 막지 않는다.
- 사용자별 Movie·영상 복제를 피할 수 있다.

### 감수하는 점

- 권리 확인 과정이 운영자 개인의 수작업에 의존한다.
- 승인 이력과 만료를 애플리케이션에서 자동 추적하지 못한다.
- 사용자 수가 늘어나면 누락과 일관성 문제가 발생할 수 있다.
- 현재 정책은 불특정 다수가 이용하는 공개 서비스에 그대로 사용할 수 없다.

## 완료 기준

MVP 단계에서는 다음 상태를 충족하면 된다.

- 서비스 대상이 운영자가 확인한 소수 사용자로 제한된다.
- 영상 업로드 전에 운영자가 권리 관계를 수동 확인한다.
- 권리가 불명확한 작품은 영상 없이 필모그래피만 제공한다.
- User·Person 탈퇴가 공유 Movie 삭제로 전파되지 않는다.
- Movie 삭제는 별도 관리 행위이며 소유 자식과 파일을 안전하게 정리한다.
- 공개 서비스 전환 전에 이 문서를 재검토하고 자동 권리 관리 기능을 설계한다.
