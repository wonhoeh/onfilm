# Refresh token 재사용 대응 정책

## 결정

폐기된 refresh token의 재사용이 감지되면 해당 사용자의 refresh token을 모두 삭제한다.
현재 서비스는 여러 기기의 로그인 세션을 독립적으로 유지해야 하는 요구사항이 없으므로,
토큰 계열이나 기기별 세션을 구분하지 않고 사용자 단위로 대응한다.

## 이유

- 폐기된 토큰의 재사용은 토큰 탈취 가능성이 있는 보안 이벤트다.
- 사용자 단위 전체 폐기는 구현이 단순하고 탈취된 세션의 범위를 알 수 없을 때 안전하다.
- 현재는 다른 정상 기기의 세션까지 종료되는 비용보다 보안상 확실한 차단을 우선한다.

## 트레이드오프

- 한 기기의 토큰이 재사용돼도 같은 사용자의 모든 로그인 세션이 종료된다.
- 여러 기기 로그인을 본격적으로 지원하면 정상 세션에 미치는 영향이 커질 수 있다.
- 기기별 세션이 필요해지면 `familyId` 또는 `sessionId`를 저장하고 해당 토큰 계열만
  폐기하는 정책으로 변경해야 한다.

## 로깅 정책

- 재사용 감지 시 사용자 ID와 이벤트를 WARN 수준으로 기록한다.
- 원문 refresh token과 token hash는 로그에 기록하지 않는다.
- 클라이언트에는 재사용 여부를 구체적으로 노출하지 않고 공통 401 오류를 반환한다.

예시:

```text
WARN Refresh token reuse detected; deleting all sessions for userId=123
```

## 만료 토큰 접근 기록

만료된 refresh token으로 회전을 요청하면 `lastUsedAt`과 `revokedAt`을 별도의
`REQUIRES_NEW` 트랜잭션에서 저장한 후 401을 반환한다. 외부 회전 트랜잭션이
예외로 롤백되더라도 만료 토큰 접근 기록은 보존한다.

## 보존 기간

만료되거나 폐기된 토큰은 기본 30일 동안 보존한 뒤 매일 정리한다. 보존 기간은
`auth.refresh-token-retention`, 실행 시각은 `auth.refresh-token-cleanup-cron`으로
설정한다.
